# 后续开发计划

本文档记录 Feishu Agent Notifier 的后续开发方向。它不是功能评分表，也不承诺具体完成日期；实际开发顺序以用户反馈、安全边界和维护成本为依据。

## 开发原则

- 保持 Feishu-first，不为了扩展平台数量而削弱现有配置体验。
- 优先使用 Codex、Claude Code 和飞书提供的公开协议与 Hook，减少对版本内部实现的依赖。
- 远程输入默认拒绝，权限提升必须由用户明确选择。
- 凭据与普通数据分离，磁盘持久化内容可配置、可清理、可解释。
- 新增关键链路时同步补充单元测试、Extension Host 测试和升级验证。
- 保持插件轻量；Session Broker 仅按需启动、监听回环地址，不安装系统服务或开放局域网端口。

## 近期计划

### 安装与升级

- 覆盖旧版本到当前版本的真实 Windows 和 Linux 升级测试。
- 扩展 Extension Host 测试，覆盖 SecretStorage 迁移、数据目录切换和配置热更新。
- 增加最低支持版本与最新版本的 Codex、Claude Code 真实链路冒烟测试。
- 为 Hook 安装、修复和卸载增加更直观的差异预览。

### 会话与远程回复

- 改进 Codex 和 Claude Code 分支来源展示，在会话列表中同时显示源 session 与当前远程 session。
- 增加远程分支归档、解除绑定和安全清理入口。
- 提供单次远程任务权限覆盖，不要求修改全局执行策略。
- 为冲突、超时、取消和 Agent 版本不兼容提供更明确的飞书回执。

### 通知与内容控制

- 增加项目和消息来源的允许/拒绝规则。
- 增加安静时段和本地免打扰策略。
- 提供可配置的敏感内容遮盖规则，并在发送前显示命中结果。
- 当飞书拒绝某种 Markdown 结构时自动降级为兼容卡片或纯文本。

## 中期计划

### 投递记录

- 增加可搜索的本地投递记录，只保存必要元数据，正文存储由用户单独选择。
- 显示每条消息的尝试次数、失败原因和最终目标。
- 提供重试、丢弃、导出诊断摘要以及队列保留期限和容量设置。

### 远程开发环境

- 支持 WSL、Remote SSH 和 Dev Container 的环境识别与 Hook 安装。
- 明确区分本机、远程主机和容器中的 session，并避免跨环境误路由。
- 增加多 VS Code Profile 的设备标识、端口协调和会话选择。

### 开源维护体验

- 增加中英文包本地化。
- 补充图标、截图、演示流程和问题排查模板。
- 增加可脱敏的支持信息导出，方便提交 Issue 时复现问题。

## 长期探索

- 可选的系统服务模式，使 VS Code 完全关闭后仍能接收新的飞书消息；当前 Session Broker 已解决窗口重载和活动 Codex turn 存活，但飞书长连接仍属于 Extension Host。
- 可选的多设备中继，提供设备选择、端到端认证和明确的离线状态。
- 在统一 provider 接口后增加其他通知目标，同时保留飞书作为默认和首要支持对象。
- 把现有文本审批命令升级为带签名动作的飞书交互卡片，并补充超时、撤销和审计视图。

## 当前不计划

- 不修改 Codex 或 Claude Code 源码。
- 不默认开启公网监听、端口转发或云端中继。
- 不默认保存完整对话历史、思考内容、工具参数或工具输出。
- 不自动继承高权限；`inherit` 继续要求用户显式启用。
- 不将多个正在运行的 IDE/CLI 进程伪装成同一个可并发写入的 session。

## 提议新功能

提交 Issue 时建议包含：使用场景、期望行为、安全影响、是否需要持久化、涉及的 Codex/Claude Code/VS Code/飞书版本，以及能够接受的兼容边界。实现前优先确定公开协议是否支持，再决定插件内的最小实现。
